# Випуск 5.9.0: архів адрес без втрати даних

## Результат

- Неактивну адресу можна перенести в архів, не видаляючи її історію, тарифи, оплати, постачальників, власні послуги та майбутні поля даних.
- Після архівації застосунок автоматично відкриває іншу активну адресу, а чернетка попередньої адреси спочатку зберігається на пристрої.
- Архівні адреси не потрапляють до щоденного перемикача, порівняння, зведеного звіту та Push/Telegram-нагадувань.
- Адресу можна відновити одним натисканням. Усі дані повертаються без перетворення.
- Остаточне видалення доступне лише в архіві після точного введення назви адреси. Після видалення є коротка дія «Відновити».
- Вікно адрес отримало окремі секції «Активні» та «Архів», зрозумілі стани, великі кнопки й м’яке оформлення в поточній палітрі.

## Сумісність даних

Архів використовує одне необов’язкове поле адреси `archivedAt` з ISO-датою. Старі адреси без нього вважаються активними. Структура записів і всі невідомі поля копіюються без змін.

Архівація ніколи не допускається для останньої активної адреси. Сервер, локальна копія та синхронізація зберігають архівні адреси у тому самому масиві, тому окрема міграція не потрібна.

## Перевірка перед випуском

1. Модульні тести архівації, відновлення та захищеного видалення.
2. Інтеграційний тест реального інтерфейсу зі зміною поточної адреси й перевіркою вкладених даних.
3. Перевірка, що архівні адреси не створюють Push або Telegram-нагадування.
4. Повний `npm run check` і dry-run Worker.
5. Резервна копія production KV та повторна звірка перед публікацією.
