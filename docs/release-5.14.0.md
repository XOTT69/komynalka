# 5.14.0 — простіший початок і щомісячна робота

Перевірений кандидат релізу, 4 жовтня 2026 року, commit `d6da798`, build `7cb392e884d8`. [CI успішний](https://github.com/XOTT69/komynalka/actions/runs/37182705991): основні перевірки та Chromium/WebKit/Firefox. Production поки залишається 5.13.0. Це перша частина погодженого плану зростання, а не завершення всіх його етапів.

## Поведінка

- Новий акаунт отримує майстер: адреса й послуги → тарифи → попередні показники. Прогрес зберігається на пристрої окремо для акаунта. Поки майстер не завершено, він не переписує налаштування адреси. Акаунти з історією не проходять примусове налаштування.
- Невідомий попередній показник можна залишити порожнім. Явний нуль приймається. Денний/нічний і зимовий режими мають видимі позначки; зимовий тариф перевіряється окремо. Зміна адреси/акаунта закриває майстер.
- Публічне `demo.html` працює з вигаданими числами без читання сховища акаунта й запитів до API. Розрахунок і текст листа доступні до реєстрації, копіювання має явне підтвердження. Демо не надсилає листів.
- Підсумок місяця показує нараховано, оплачено, залишок, послуги й зміну суми до сусіднього місяця. Доступний для перегляду та копіювання; запланована автоматична розсилка підсумків ще не реалізована.
- Історія показує по 48 записів. Пошук, загальні підсумки та графіки використовують повний набір; дія «Оплатити видимі» застосовується лише до видимих рядків. Наступні сторінки не видаляють старих даних.
- Telegram/Push передають ідентифікатор потрібної адреси в посиланні. Клієнт перевіряє, що адреса належить поточному акаунту та активна. Передані показники, час за Києвом, відкладення й відмова від каналу зберігають попередню поведінку.
- «Мої звернення» повертає статус лише автору за квитанціями останніх 20 звернень. Контакти й логін не повертаються цим endpoint. Звернення до входу не відкриваються чужому акаунту. Старі заявки без квитанцій не з’являються автоматично в новому списку.
- Лендінг і три інструкції використовують ніжну палітру, пояснюють реальні можливості. Поширення й нагадування використовують mykomunalka.pp.ua; старі домени та ідентичність установленої PWA залишаються чинними.

## Старт і сумісність

Скрипти запускаються в порядку `defer`; Firebase більше не блокує розбір HTML. AI, зображення звіту й підсумок завантажуються при відкритті, але залишаються у повному кеші для офлайн. Заставка не має обов’язкової паузи 600 мс. Порядок Google redirect/popup та same-origin auth helpers збережено. Кнопка оновлення повертається в доступний стан, якщо кандидат змінився або повідомлення Worker не вдалося надіслати.

Build budget контролює gzip розміри стартових JS і HTML. Поточна оцінка — приблизно 155 KiB JS та 30 KiB HTML; це не вимірювання LCP/INP або швидкості фізичного телефона. HTML приватного застосунку позначено noindex; sitemap містить лише публічні сторінки. У початковому GA page view URL передається без query/hash, referrer не передається. Нову аналітику воронки не ввімкнено.

Namespace KV, ACCOUNT_STORE, sync protocol v2, дані адрес і попередні записи не замінюються. Viewport `user-scalable=no` збережено за інструкцією власника. Резервні копії не потрапляють у Git або Vercel.

## Перевірка кандидата

- `npm run check`: 172 тести, syntax/build/sanity/UI smoke та контроль розміру стартових ресурсів — успішно.
- Реальні браузерні сценарії Chromium/WebKit: 390 і 1440 px, майстер і його відкладення, чернетка після reload, посилання адреси, підсумок, історія, демо. Firefox на Mac не запускає тестовий профіль, але той самий сценарій успішно пройшов у Linux CI. Усі три browser jobs завершені успішно.
- Верстка: 320/390/768/1440 px, світла/темна теми; нижнє меню, поля, пошта, історія й AI пройшли перевірку. Великий текст перевірено без зміни viewport policy.
- PWA: перше встановлення, оновлення двох вкладок, їхні різні чернетки, збій API, офлайн reload, відсутність кнопки за незмінної версії. Один початковий запуск очікував навігацію до timeout; повтор на новому ізольованому сервері та остаточний CI пройшли.
- Worker dry-run пройшов. Ізольоване відновлення workerd/SQLite: 2 вигадані акаунти, 2 адреси, 2 записи, 5 KV keys; сесії відкликано. `npm audit --audit-level=high`: 0 вразливостей.

## Резервування та публікація

Збережено приватну зашифровану infrastructure-копію попереднього Worker/settings і 97 сирих KV keys; інвентар стабільний. Це ще не повний canonical recovery: актуальні DO snapshots мають бути додані й перевірені окремо. Наявна попередня повна recovery-копія 5.13.0 зберігається.

Автоматична перевірка дозволів відхилила підготовку DO/KV capture, оскільки вона може тимчасово призупинити production-записи. Власнику надіслано окремий запит на паузу до 10 хвилин. До відповіді capture, production deploy та просування main не виконуються. Health перевірено: `version:5.13.0`, `readOnly:false`, `syncProtocol:2`.

## Наступні частини плану

Автоматичний зашифрований R2 backup потребує вибору приватного сховища й ключа; [конкретна пропозиція](automatic-backup-proposal.md) підготовлена, запуск не ввімкнений. Серверна пагінація/індекси адмінки, лабораторне навантаження, вимірювання на фізичних телефонах, моніторинг і opt-in розсилка підсумків — окремий наступний пакет. [Запрошення для тестової групи](beta-launch-2026-10.md) підготовлено, нікому не надсилалося.
