# Випуск 5.8.0: підтвердження оплати та пояснення споживання

## Результат

- Для статусів «Частково» і «Сплачено» можна зберегти дату оплати та необов’язковий номер квитанції або банківської операції.
- Поля підтвердження входять до адресної чернетки й відновлюються після закриття або офлайн-перезапуску.
- Дата й номер видно в деталях відповідного місяця в історії.
- Номер операції не додається до тексту функції «Поділитися».
- Перед збереженням застосунок порівнює введене споживання води, гарячої води, світла й газу з останніми трьома попередніми місяцями.
- Пояснення з’являється лише для помітної зміни та щонайменше двох придатних історичних значень. У ньому показані поточне значення, середнє й відсоток різниці.
- Розрахунок винесено в окремий модуль `consumption-insights.js`, який не змінює записи.

## Сумісність даних

Нові необов’язкові поля запису:

- `paymentDate` у форматі `YYYY-MM-DD`;
- `paymentReference` до 120 символів.

Старі записи без цих полів працюють як раніше. Перехід у стан «Нараховано» прибирає лише підтвердження оплати цього запису. Показники, тарифи, суми, історія, адреси та невідомі поля не змінюються.

## Перевірка перед випуском

1. Повний `npm run check` і dry-run Worker.
2. Перевірка чернетки офлайн, редагування старого запису й конфліктів синхронізації.
3. Повна резервна копія Worker і KV з повторною звіркою значень.
4. Перевірка production HTML, Service Worker і health endpoint після публікації.
