# Випуск 5.2.0: стан даних, швидший старт і PWA-навігація

Цей випуск не змінює формат акаунтів, адрес, записів, тарифів, нагадувань або карток постачальників. Cloudflare Worker, KV-ключі, Durable Object і протокол синхронізації залишаються сумісними з 5.1.0.

## Зміни

- У «Дані та резервні копії» додано стан синхронізації, час останньої успішної хмарної копії, дату останнього JSON-експорту, наявність локальних змін і версію застосунку.
- Версія production-збірки береться з `package.json`; service worker продовжує використовувати content hash, тому банер оновлення з'являється лише для іншої збірки.
- Ярлик встановленої PWA «Внести показники» відкриває форму показників.
- jsPDF і AutoTable завантажуються лише під час створення PDF. Вони та великі необов'язкові файли не блокують встановлення основного офлайн-комплекту.
- Перший запуск показує три конкретні кроки налаштування.
- У користувацькому `index.html` немає inline-обробників подій; закриття модальних шарів і кнопки підключені через JavaScript.

Єдиний новий локальний ключ — `komynalka_device_meta_v1:<account>`. Він містить тільки час останньої синхронізації та JSON-експорту. Видалення цього ключа не видаляє й не змінює облікові дані.

## Перевірка перед публікацією

1. Створити й перевірити повний production-бекап за чинною процедурою.
2. Виконати `npm ci --ignore-scripts`, `npm run check`, `npm run build` і `npm run worker:check`.
3. Перевірити demo на 390 px і 1440 px: Огляд, Показники, «Дані та резервні копії», fixed-навігацію й темну тему.
4. Після deployment відкрити чинний акаунт, переконатися, що кількість адрес і записів не змінилась, а статус синхронізації показує успіх.
5. Створити JSON-бекап із UI та перевірити, що дата експорту з'явилась у центрі стану даних.
6. Перевірити встановлену PWA: ярлик «Внести показники», офлайн-відкриття й відсутність банера «Оновити» після повторного запуску тієї самої збірки.

## Відкат

Для відкату достатньо повернути попередню статичну збірку 5.1.0. Серверний формат не змінювався, тому відновлювати або перезаписувати KV через відкат інтерфейсу не потрібно. Нові валідні записи, створені у 5.2.0, залишаються сумісними з 5.1.0. Перед відкатом не треба імпортувати старий snapshot поверх новіших даних.
