# Резервування й перевірка відновлення

Актуальний формат — `komunalka-recovery-v2` всередині `komunalka-encrypted-backup-v1`. Джерело акаунтів — Durable Objects; KV mirror сам по собі недостатній. Старий `restore-kv-archive.mjs` призначений для історичних raw KV архівів і не замінює сучасне recovery.

## Створення копії

В адмінці: «Налаштування → Дані → Повний бекап». Ввести окремий пароль не коротший за 12 символів. Зберігати його окремо від архіву. Копія включає credentials, підписки, Telegram IDs, гостьові токени та KV — не надсилати її у звичайну форму відгуку або AI.

Копіювання повторно звіряє список акаунтів і revisions. Під час активних змін експорт може відмовити й попросити повторити. Для міграції потрібен режим `MAINTENANCE_MODE=read-only`, зупинені зовнішні writers і окрема перевірка нерозпізнаних legacy values. Сам факт download не підтверджує recovery.

## Rehearsal

```sh
npm run backup:restore-check -- /absolute/path/komunalka_recovery.encrypted.json
```

Команда спочатку збирає Worker без deploy, запитує пароль у терміналі з прихованим введенням і відновлює в локальній ізольованій SQLite/Miniflare. Зовнішні запити вимкнені. Перевіряє checksum/schema/counts, account value/revision, канали, реєстр і відкликані доступи, каталог тарифів. Активні сесії завершуються. Пароль не передавати в аргументах команд чи environment. Production-команди відновлення цей скрипт не виконує.

Незашифровані тестові canonical archives можна додатково перевірити `npm run backup:verify -- /absolute/path/test.json --for-migration`. Не створювати незашифровані production-копії для зручності; encrypted rehearsal перевіряє той самий вміст після дешифрування в пам’яті.

## Справжнє відновлення

Після успішного rehearsal погодити ціль, read-only, актуальну приватну копію цілі, mappings/secrets і наслідки для сесій. Використати ту саму структуру authority snapshots; не підміняти актуальний DO старішим KV mirror. Credentials збережені, а сесії після recovery користувачі отримують новим входом. Просте повернення старого share KV не скасовує revocation, якщо реєстр DO відновлений разом з копією. Політика retention для завантажених архівів задається власником сховища; застосунок не може видалити вже скачані файли дистанційно.
