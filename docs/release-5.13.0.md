# 5.13.0 — результати реалізації аудиту

Опубліковано 3 жовтня 2026 року: https://komynalka.vercel.app/ і прив’язані mykomunalka.pp.ua / www.mykomunalka.pp.ua. Worker version ID: `7d6afbc8-e361-479c-bac9-3b01346faec1`. База — 5.12.0 / a308d5d. Введені дані, KV Namespace, Durable Object binding, Firebase project і протокол синхронізації v2 не замінюються. Viewport із забороною масштабу залишений за інструкцією власника.

## Реалізовано

- Гостьовий API повертає дозволені поля адреси, записів і вкладених об’єктів. Особові рахунки, контакти, нотатки, paymentProof і реквізити оплати не передаються. Кожне читання перевіряє реєстр доступу й строк дії. Старі share_ посилання мігрують; їхній KV expiration зберігається, а для безстрокових задається 30 днів від міграції. Понад 30 нових посилань створення відхиляється; старі імпортовані доступи залишаються видимими й можуть бути відкликані. Невдалий запис нового токена не залишає прихованого доступу.
- Реєстрація через legacy save закрита; явна реєстрація й перевірений Google onboarding залишені. Старий акаунт мігрує після перевірки пароля. Системні імена зарезервовані. Capitalized legacy names індексуються один раз; невдалий вхід більше не запускає повний KV scan щоразу.
- Експорт акаунта імпортується через preview. Можна об’єднати дані зі збереженням поточних значень або замінити їх. До зміни створюється локальна копія; невідомі поля підтримуваного формату зберігаються. Помилка quota не повинна застосовувати незбережену копію.
- В акаунті показано активні Worker-сесії, поточний пристрій і строки входу; можна завершити іншу або всі інші сесії. Google-керування позначене окремо. Підтвердження прив’язані до власника акаунта.
- Видалення прибирає приватний DO-стан, попередню копію, legacy-original, канали, сесії й локальні ключі власника. Технічні прив’язки після тимчасового збою KV прибирає повторний alarm. Старий credential mirror видаляється до основного очищення; пізня sync-відповідь не відновлює локальні дані. Мінімальний tombstone перешкоджає запису старою чергою. Раніше завантажені копії не видаляються дистанційно.
- AI-запит прив’язаний до власника й покоління чату; вихід, очищення й перемикання скасовують стару відповідь. До 200 повідомлень зберігаються локально, до API передаються останні 10. Є повтор, скасування, копіювання й повідомлення про обмежену відповідь. Дані Комуналки вимкнені за замовчуванням; після згоди використовуються точні залишки часткових оплат, нульові та історичні тарифи. Загальні питання залишаються доступними. Хмарного збереження історії немає.
- Нагадування показують останню спробу й результат каналу; API-успіх названо прийняттям повідомлення, а не прочитанням. Порожній вимкнений стан пояснюється. Чинні вибір часу, календар, snooze і завершення передачі збережені.
- Заміна лічильника: дата, попередній/кінцевий показник старого й стартовий нового. За місяць рахується старий відрізок плюс споживання нового. Чернетка зберігається офлайн; потрібен поточний показник нового лічильника. За реєстр дозволена одна подія в місяці, яку можна редагувати/прибрати. День і ніч рахуються окремо. Історія, CSV, аналітика, лист і AI використовують спільний helper; незмінені історичні нарахування зберігаються.
- Відгуки після 500 записів видимі; API має сторінки й cursor за останнім записом. Додавання нового звернення між сторінками не зсуває вже переглянуту межу. Адмінські зміни записуються у приватний журнал без паролів/токенів/текстів оголошень: останні 100 у UI, записи до 365 днів. Health перевіряє доступність KV/DO; стан інтеграцій — конфігурація, без секретів і без неправдивого підтвердження доставки.
- Операційна копія містить актуальний DO-стан, credentials, канали, реєстр доступів і сирі KV/mappings. Файл шифрується AES-256-GCM, пароль виводиться через PBKDF2-SHA256. Є checksum, manifest і перевірка фактичного відновлення в ізольованому workerd/SQLite. Активні сесії навмисно не відновлюються. Нерозпізнані старі KV-значення зберігаються сирими; їх не можна вважати перевіреними акаунтами для міграції.
- Пастельні спільні компоненти й темна тема: компактніший Огляд, зрозумілі статуси, форми імпорту/заміни, сесії, AI. Непідключені auth/share стилі перенесено вибірково. Нові account/import і meter UI відокремлені від app.js; JS/CSS адмінки винесені у файли.
- Єдина версія 5.13.0 і content build ID. При активації наступної версії інші відкриті вкладки зберігають чернетки перед перезавантаженням. Перший install не показує фальшивого оновлення. Повний offline bundle перевіряється до активації.
- Відсутній попередній показник не перетворюється на нуль: форма пояснює помилку й не зберігає неправильне нарахування. Явний нуль підтримується. При помилці прибираються застарілі суми з карток і підсумку. Аналітика пропускає незаповнені показники, а не показує удаване заощадження 100%.
- Нульові тарифи проходять збереження шаблону, налаштувань і повторне відкриття офлайн; від’ємні відхиляються. Нічний коефіцієнт, зимовий ліміт і невідомі додаткові поля зберігаються. Історичні нарахування не перераховуються.
- Відповіді Push/Telegram і спроби входу прив’язані до акаунта й сесії: запізніла відповідь після нового входу не змінює його канали й не відкриває посилання попереднього власника.
- Автоматичний вхід відновлює раніше збережену копію акаунта при мережевому збої, 5xx або некоректній успішній відповіді API, навіть якщо браузер повідомляє online. Явний вхід і підтверджена відмова авторизації не використовують цей fallback. Відкликана сесія прибирає локальні дані входу, зберігаючи бізнес-копію для подальшого входу. Чернетки й ознака парольного акаунта відновлюються.
- CI перевіряє синтаксис, build, поведінкові тести, Worker dry-run, залежності й браузерні сценарії на вигаданому акаунті. Tailwind збирається офіційним one-shot Node compiler без file watcher; уразливий dev-ланцюжок вилучений. Tailwind 4 потребує сучасного браузера: Safari 16.4+, Chrome 111+, Firefox 128+.

## Подальша робота, яка потребує окремих умов

Автоматичні щоденні зашифровані production-копії потребують обраного приватного сховища, ключа й політики retention; браузерний download не є автоматичним backup. Зовнішні alerts і виміряне навантажувальне тестування також потребують середовища. Відновлення пароля без входу можливе після підтвердженого контакту/володіння Google; довільний email у логіні не підтверджує володіння. Кілька AI-чатів та хмарна історія залишаються окремим opt-in доповненням. Подальше розділення app.js виконується поступово за сценаріями, щоб не зламати чинні функції. Ці пункти не позначені як готові.

## Виправлення Google bootstrap після публікації

На `mykomunalka.pp.ua` відтворено `auth/internal-error` при натисканні Google-входу. Firebase 12.18.0 динамічно завантажує `https://apis.google.com/js/api.js`; production CSP не дозволяла цей script origin. SDK повертає саме `internal-error` в обробнику помилки завантаження цього скрипта. До `script-src` додано лише точний `https://apis.google.com`; захист від embedding, сторонніх скриптів і object sources залишено.

Deployment config тепер входить до content build ID: інакше зміна лише HTTP headers не створювала новий Service Worker, а кешований HTML залишав стару CSP. Нова збірка — `78dd8e410b54`, версія 5.13.0. Оновлення використовує чинний механізм збереження чернеток; account mappings, Firebase project, KV/DO та дані не змінені. Worker повторно не публікується.

`npm run check` пройшов із 150 тестами; додаткова перевірка фактичного build ID у HTML/SW теж пройшла (разом 151 тест). [CI для bootstrap fix](https://github.com/XOTT69/komynalka/actions/runs/37131926542) успішний. Production content ID цієї публікації — `5527f7f702b8`; всі перевірені asset bytes збігаються з локальними. У робочому браузері через кнопку «Оновити» застосовано новий SW, а потім фактично пройдено Google-вхід у чинний mapped account `xott69`; стан показує «Google підключено». Дані адреси й історія підтягнулися. Доказ: `test-results/google-auth-fixed.png`. Власник окремо підтвердив роботу у браузері й на ПК, але повідомив, що iPhone PWA не відкриває popup.

Для iPhone/iPad standalone опубліковано redirect flow. Auth helpers проксуються на тому самому origin через Vercel rewrite до чинного `pwakomun.firebaseapp.com`, без 302; лише службовим auth-сторінкам дозволено same-origin embedding, основний застосунок зберігає DENY/frame-ancestors none. SDK використовує поточний дозволений production hostname як authDomain. Auth helpers виключено з offline SW, live OAuth responses не кешуються. Після повернення перевірений Firebase result використовує чинний Worker login/mapping. Прив’язка до парольного акаунта й далі потребує його пароля. Перед навігацією зберігаються чернетки; у sessionStorage є лише тип дії, власник і час, без credentials/tokens. Скасування, помилка й запізніла відповідь не замінюють інший акаунт. JSON response policy канонізується для build ID, щоб форматування конфігурації чи metadata хостингу не створювали фальшивих оновлень.

`npm run check` для redirect flow пройшов: **161 тест**, syntax/build/sanity/UI smoke. Після підтвердження власника 3 жовтня 2026 року Google повернув «OAuth client saved»; повторне відкриття Web client підтвердило три нові URI `/__/auth/handler` для mykomunalka.pp.ua, www.mykomunalka.pp.ua та komynalka.vercel.app і збереження попереднього Firebase URI. OAuth scopes і credentials не змінені. Доказ: `test-results/google-pwa-callbacks-saved.png`. Код `159bbcb` опубліковано; [CI](https://github.com/XOTT69/komynalka/actions/runs/37133337438) успішний. Production/local content ID збігаються: `1c219a631246`; звірено всі 41 offline assets і SW на трьох адресах. Для iframe/handler/iframe.js підтверджено 200, same-origin framing та no-store. SDK отримує конфігурацію явно з app.js, а не через init.json. Через штатну кнопку застосовано оновлення попереднього кешу. У браузері www.mykomunalka.pp.ua фактично пройдено новий Google-вхід через same-origin helper і повернення до чинного mapped account xott69. Доказ: `test-results/google-same-origin-login.png`. Фізичний iPhone/iPad standalone після публікації перевіряє власник; локальні моки й desktop popup не підтверджують поведінку iOS.
