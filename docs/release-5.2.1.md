# Випуск 5.2.1: надійні нагадування

Hotfix виправляє пропущене нагадування, коли активний період уже почався, а підписку, налаштування або server alarm було змінено після щоденної перевірки о 09:00.

## Зміни

- Підписка, вхід у застосунок і зміна синхронізованих даних ставлять найближчу перевірку через кілька секунд. Після неї зберігається щоденний розклад на 09:00 за Києвом.
- Перевірка статусу відновлює відсутній або застарілий Durable Object alarm.
- Увімкнення нагадувань одразу зберігається локально та синхронізується з хмарою.
- Активний банер нагадування перенесено з прихованих «Деталей місяця» на головний екран.
- Діапазони на кшталт 20–25 та перехід через межу місяця використовують ті самі правила у застосунку й у фоновій доставці.

Формат акаунтів, адрес, історії та KV не змінено. Наявні push-підписки зберігаються; після першого відкриття 5.2.1 сервер повторно перевіряє їхній розклад.

## Перевірка

- `npm run check`
- `npm run worker:check`
- окремі тести для періоду 20–25, негайного alarm після підписки, відновлення alarm під час входу та повторної перевірки після зміни нагадування

Перед production-deploy потрібно створити новий приватний KV-backup, розгорнути Worker без зміни bindings/secrets, опублікувати frontend і перевірити production health та хеші статичних файлів.
