# Постачальники та швидке введення — 12 вересня 2026

## Поведінка

У розділі «Постачальники» можна зберегти назву, особовий рахунок, посилання на кабінет і контакт для кожної активної послуги вибраної адреси. Перехід зі справ поточного місяця одразу обирає цей місяць. Окремий перемикач дозволяє копіювати показники з історичного запису.

Кнопки копіюють рахунок або збережені показники. Незбережена чернетка, відсутній місяць і явно незаповнена послуга не видаються за збережені показники. Копіювання не позначає передачу чи оплату виконаною. Якщо Clipboard API недоступний, відкривається текст для ручного копіювання. Кабінет відкривається лише натисканням користувача; приймаються тільки HTTP/HTTPS-посилання без вбудованого логіна/пароля.

Для додаткових послуг доступна картка постачальника й копіювання рахунку; грошова сума не видається за показник лічильника. Вимкнення послуги приховує її картку, зберігаючи налаштування до повторного ввімкнення. Періоди передачі беруться з наявних нагадувань, окремого календаря або нової автоматичної доставки немає.

У формі можна згортати заповнені лічильники, розгортати всі, переходити до наступної послуги чи підсумку. Enter переходить між полями без випадкового збереження. Відомі попередні показники пропускаються при переході з поточного поля. Значення лишаються в DOM і чернетці; валідація перевіряє активні послуги навіть у згорнутому стані. Нативна помилка поля розгортає відповідну картку.

## Зберігання

Картки — необов’язкове поле `accountSettings.providerCards`, згруповане за ключами `address:<id>` і `service:<id>`. Додаткові послуги використовують префікс `custom:`. Поле створюється лише при явному збереженні картки. Воно проходить через чинні локальні конверти, чергу синхронізації, конфлікти та JSON-експорт/імпорт.

Адреси, записи, історичні тарифи та версія схеми не мігруються. Новий код не переписує наявні production-акаунти при публікації. Backend і KV Namespace ID залишаються чинними. Гостьовий API повертає адресу без `accountSettings`, тому приватні картки не потрапляють до гостьового посилання.

Збереження спочатку підтверджується локально. Якщо локальний запис не вдався, редактор зберігає поля й дозволяє повторити спробу. Якщо відкрита картка змінилася через синхронізацію, застарілий редактор відмовляється її перезаписувати. Інші адреси та невідомі поля зберігаються.
