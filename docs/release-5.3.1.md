# Випуск 5.3.1: екран входу та діагностика Google

## Причина та виправлення

- Декоративний елемент усередині картки входу через загальне CSS-правило отримував `position: relative` замість `absolute`. Він займав 160 px над полем логіна. Елемент прибрано; логотип і форма тепер утворюють компактний екран.
- Google-вхід відкриває сторінку Google у звичайному Chrome. У вбудованих браузерах або при блокуванні спливного вікна Firebase може повернути помилку. Замість короткого зникаючого повідомлення застосунок показує конкретну помилку в самій формі і, коли доречно, дає скопіювати адресу для відкриття в Safari/Chrome.
- Під час очікування Google-входу кнопка захищена від повторного натискання. Закриття спливного вікна більше не минає без повідомлення. Це не переводить користувача на новий акаунт і не змінює збережені дані.
- Якщо сайт відкрито зі старого PWA-кешу, при старті, поверненні на вкладку або відновленні інтернету перевіряється новий service worker. Банер «Оновити» з'являється лише коли справді є встановлена інша збірка. Очищення site data не потрібне.

## Перевірка

Мобільний екран перевірено в Chrome на ширині 390 px: логотип видно, форма починається без порожнього блоку. Автоматичний сценарій перевіряє блокування й закриття Google-вікна, видиме пояснення та відсутність змін у локальному акаунті. Вхід із реальним Google-акаунтом не автоматизовано, бо для нього потрібні особисті облікові дані користувача.

Firebase прямо попереджає, що popup-вхід може блокуватися пристроєм або платформою, а redirect-вхід на зовнішньому хостингу потребує окремого налаштування auth-домену. Тому неналаштований redirect як автоматичний запасний шлях не додано.
