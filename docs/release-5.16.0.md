# 5.16.0 — надійність і вимірювання швидкості

Опубліковано 4 жовтня 2026 року на mykomunalka.pp.ua, www.mykomunalka.pp.ua та komynalka.vercel.app. Код `d31314c`, build `4f1874aa3f55`. Основні дані акаунтів, чинні KV Namespace та ACCOUNT_STORE, Google-вхід, поштові шаблони, нагадування й viewport policy зберігаються. Нова база даних, зовнішній збирач помилок або R2 не додаються.

## Зміни

- У розділі адмінки «Безпека» — «Надійність сервісу»: періоди сьогодні/7/14 днів, загальні запити, збої API, конфлікти збереження й збої надсилання нагадувань. Нульові значення показуються явно; невдала перевірка прибирає старі цифри й показує стан невідомим.
- Фіксовані категорії входу, реєстрації, прив’язки Google, завантаження/збереження, пароля, підключення/тесту каналів, команд Telegram, звернень, AI та нагадувань. HTTP результати окремо розрізняють успіх, відмову доступу, конфлікт, обмеження частоти, відхилення, застарілу push-підписку й серверний/мережевий збій.
- Для часу відповіді використовується обмежена гістограма; P95 — верхня межа групи, а не точне вимірювання 95-го процентиля. Час мережі до пристрою сюди не входить.
- «Прийнято» для нагадування означає відповідь провайдера, а не прочитання/показ на телефоні. Пропущений або вже надісланий сьогодні reminder не збільшує лічильник спроб. Повтори після збою та очищення 404/410 push-підписок збережені.
- Агрегати по UTC-добах зберігаються у службовому DO `__service_metrics__` в існуючому binding, до 14 днів з автоматичним alarm-очищенням. Фоновий запис через [Cloudflare waitUntil](https://developers.cloudflare.com/workers/runtime-apis/context/#waituntil) з обмеженим очікуванням не блокує відповідь користувачу, а невдалі записи можуть бути пропущені. Це діагностика, не білінг і не повний журнал.
- Немає окремих подій, IP, логінів, UID, адрес, показників, токенів, URL, текстів звернень, листів або AI-розмов. Лічильники читаються лише через чинну адмінсесію; публічний API не дає їх змінювати чи читати. Правила описані на сторінці приватності.
- Збої Firebase/Google у браузері до запиту нашому Worker не потрапляють у ці серверні лічильники. Автоматичного збору браузерних логів немає.
- Відтворювана лабораторія `npm run measure:performance`: 200 і 1000 вигаданих записів, 5 свіжих Chromium-контекстів, 390×844, CPU ×4, мережа 70 мс / 10/5 Мбіт/с, тільки localhost. CI виконує по 3 повтори та зберігає JSON artifact.

## Перевірено локально

188 тестів пройшли: категорії/приватність/ретенція/доступ, збереження при відмові моніторингу, щоденна дедуплікація й повтори нагадувань, порожні/нульові стани адмінки. Worker dry-run пройшов. Реальний ізольований workerd/SQLite: 40 акаунтів, 8 800 записів, 100 паралельних адмінзапитів, 10 конкурентних записів (1 прийнято, 9 конфліктів); 40 читань записані через справжній background context. Історію збережено.

Chromium і WebKit у 390/1440 px пройшли критичні сценарії, новий блок і зміну його періоду. Усі чотири CI jobs, включно з Firefox, лабораторією та PWA, завершилися успішно: [CI для релізу](https://github.com/XOTT69/komynalka/actions/runs/37190584274).

Локальний baseline: медіана готовності Огляду 1,534 с / 2,091 с для 200/1000 записів; відкриття історії 257 / 228 мс. Це не результати фізичного телефона або production. Помітна тривала задача на великій історії — привід для наступного профілювання. Усі повтори: [baseline](performance-baseline-5.16.0.json). [Протокол фізичних телефонів](phone-performance-checklist.md) підготовлено, фізичні тести ще не виконані.

## Що залишається

Фізичні телефони та реальна мережа ще не виміряні. Наступні роботи: профілювання тривалої стартової задачі на великій історії, пагінація журналу адміндій, пробний запуск із людьми, політика витрат і opt-in розсилка підсумків місяця. Цей реліз не означає завершення всього плану зростання.
