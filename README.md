# Комуналка

Облік комунальних платежів українською: адреси, показники, історія, часткові оплати, тарифи, аналітика, нагадування, звіти та гостьовий доступ. Статична PWA + Cloudflare Worker, KV і Durable Object на акаунт. Вхід через пароль або Firebase Google Auth. Поточний реліз — 5.12.0: сесійна авторизація, зміна пароля та контроль даних описані в [docs/release-5.12.0.md](docs/release-5.12.0.md).

## Розробка

Потрібні Node.js 22+ та npm. Канонічний lockfile — `package-lock.json`.

```sh
npm ci --ignore-scripts
npm run demo         # http://127.0.0.1:4174, вигадані дані, окреме локальне сховище
npm run demo:pwa     # http://127.0.0.1:4175, справжній Service Worker на вигаданих даних
npm run dev          # http://127.0.0.1:4173, клієнт для чинного API
```

Демо використовує Worker з пам'яттю замість production KV; реальні Google-вхід і API у ньому не використовуються. Дані демо на сервері скидаються після перезапуску. Це окремий origin від звичайного локального клієнта. HTML демо й автоматичний тестовий вхід додає лише локальний сервер: вони не потрапляють у `dist`.

```sh
npm run build        # самодостатній каталог dist; локальні JS, CSS, шрифти та PWA-кеш
npm run brand:icons  # PNG-іконки й прев’ю з brand-*.svg
npm run check        # синтаксис, перевірка наявних функцій і поведінкові тести
npm run worker:check # лише dry-run складання Cloudflare Worker, без публікації
```

Перегляд не має автоматичного перезавантаження після редагування: виконайте `npm run build`, потім оновіть сторінку. Service Worker у звичайному демо вимкнений. У `demo:pwa` локальні кнопки дозволяють перевірити наступний реліз і збій сервера; після build натисніть «Перевірити оновлення» та активуйте знайдену версію. Ці кнопки й тестові API не потрапляють у production build. Браузерний сценарій CI — `tests/pwa-browser.cjs`.

## Дані й випуск

**Production не оновлюється командою build або demo.** Фонові нагадування та оновлення PWA: [docs/push-and-updates.md](docs/push-and-updates.md). Поточний план контрольованого випуску й відкату: [docs/release-5.2.0.md](docs/release-5.2.0.md). Базовий план переходу даних збережено в [docs/release-5.1.0.md](docs/release-5.1.0.md).

```sh
npm run backup:verify -- /absolute/path/backup.json --for-migration
```

Валідатор звіряє кількості акаунтів, адрес, записів і KV-ключів, перевіряє ID та виводить SHA-256 файла без особистих даних. Він не замінює пробне відновлення й перевірку походження архіву. Резервні копії містять приватні дані та хеші паролів: тримайте їх поза Git, з обмеженим доступом і шифруванням носія.

Попередній аудит — [PROJECT-REVIEW.md](PROJECT-REVIEW.md), вимоги до реалізації — [REDESIGN-PROMPT.md](REDESIGN-PROMPT.md). Старі документи про Supabase та зміну домену не є планом цього випуску.
